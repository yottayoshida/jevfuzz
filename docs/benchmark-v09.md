# v0.9 benchmark protocol

Run `node scripts/benchmark-v09.ts --quick --out /private/tmp/jevfuzz-benchmark-v09-quick` during development. The complete local protocol is `node scripts/benchmark-v09.ts`; v3 evidence is stored in `fixtures/benchmarks/raw-v09-v3/` and refreshes `fixtures/benchmarks/results-v09.json` only after writing its explicit acceptance result. It is offline-only: all evaluations use production `campaign`, oracle, shrink, and `FakeProvider` code. It performs no network request and needs no credential. A quick smoke cannot promote feedback or establish the full statistical criterion.

The manifest freezes 12 simulator families, five strategies, seeds 0–99, a 1,000 logical-call budget, and a 5,000-attempt ceiling. Each strategy receives the same seed corpus, response function, mutation space, oracle, and phase budgets. `sources.frozen.json` binds the manifest, runtime version, runner, supplemental runner, censored-analysis helper, protocol, dependency lock, and every production source file. Each raw row carries that source hash. Resume and merge reject changed source hashes, duplicate or unexpected tuples, and incomplete final tuple coverage. Existing evidence is never overwritten by starting a fresh run in the same directory.

The primary endpoint is actual logical cost to a confirmed finding. After computing the simulator response, the harness places its unique provider invocation ordinal in `usage.input_tokens` solely as measurement provenance. It computes each finding's completion as the maximum ordinal of **all** formal A/A′/B observations, including a trailing A/control after B. Repeated payloads cannot alias observation identity. The raw row retains the first confirmation's 24 ordinals. The earliest completed confirmation defines `firstFindingLogicalCall`; `firstConfirmedCandidateOrdinal` is only a scheduler diagnostic. Unfound trials are censored at actual consumed logical calls, not at an unspent budget. Token usage from these tagged simulator trials is not a token-cost metric.

The old `raw-v09` v2 output used matching mutant wire hashes for endpoints. It remains diagnostic evidence only: a trailing A/control or later reuse of the wire makes that endpoint unsuitable for performance promotion. v3 refuses to import v2 rows. Other old metrics are not erased.

Results include censored discovery curves, discovery rate, Kaplan–Meier medians that include actual censor times, seed-unit bootstrap 95% intervals that retain non-reached medians as right-censored, unique actionable fingerprints per 1,000 actual calls, invalid-candidate count, phase costs, controls from all executed formal confirmations, confirmation samples, and behavioral signature counts. `--supplemental-only` reuses only verified v3 raw trials with the identical source freeze.

Fixed-stat calibration runs 1,000 independent simulated campaigns with `alpha=.05`, five original slots, five reserved shrink-final slots, and 64 pairs per formal test. A fixed seeded random stream returns an input-independent distribution. The production shrinker adaptively screens reductions, freezes its selected payload, and attempts a fresh final confirmation using the same ten-slot Bonferroni family. A confirmed diagnostic source from a deliberately buggy simulator supplies the parent needed to exercise the shrink route even when healthy original confirmations do not FAIL; the injected parent itself is never counted as a null false positive. The null family counts any original false FAIL or fresh confirmed child under the null, and records actual screen/final coverage and slot consumption. The one-sided 95% Clopper–Pearson upper bound must be at most .07. This intentionally exercises adaptive shrink under a healthy target; it is not a claim that an ordinary healthy campaign always has a parent finding.

Guard scenarios separately cover unknown cache metadata, cached responses, rate-limit transport uncertainty, and model drift. They do not transfer an alpha guarantee to live services. Noise and drift also have simulator families. The known-minimum shrinking suite runs ten deterministic fixtures, checks the declared expected final structure, and requires fresh final confirmation and monotonic accepted complexity reductions.

The 50-seed concurrency suite compares concurrency 1, 4, and 8. It compares committed candidate identity and the generated candidate's base/mutant wire hashes at each logical discovery event, actual confirmation A/A′/B wire hashes, accepted stable corpus identities, input hashes, formal findings, and observation counts. Physical provider invocation sequence hashes remain diagnostic because concurrent dispatch legitimately changes that order. Timestamps and elapsed time are excluded.

For bounded parallel execution, run four independent commands with `--trials-only --shard-count 4 --shard-index 0` through `3`, each using a distinct `--out` directory. Then run `node scripts/benchmark-v09.ts --merge-shards path0,path1,path2,path3 --out fixtures/benchmarks/raw-v09-v3`. The merge checks all 6,000 unique tuples and identical source hashes before running the supplemental suites and analysis. A shard completion is never full-protocol completion. Keep source files unchanged during the run; if they change, retained raw data cannot silently acquire a new source identity.

Acceptance is written as explicit booleans and the process exits nonzero for a failed protocol. It requires complete tuple coverage, no campaign runtime errors, no confirmed findings in invariant/noise families, inconclusive model drift, all known-minimum shape assertions, stable logical concurrency comparisons, exercised adaptive null confirmation with recorded coverage, passing guard scenarios, unchanged source identity, and the full-run null upper-bound criterion. Detectable family misses remain measured censored outcomes rather than being discarded or rerun for a better seed.

Feedback remains experimental by default. It can be promoted only when at least three detectable families have a feedback median confirmed-call endpoint at least 25% lower than uniform and feedback's pooled detection rate is no more than five percentage points lower, after all full-protocol acceptance checks pass. The generated decision exposes every comparison and otherwise keeps `uniform` as the default. Simulator evidence does not establish live-provider correctness or user-workload utility.

The retained 6,000-row v3 measurement run predates a correction to aggregate medians. Its original runner and protocol are preserved as `measurement-runner.frozen.ts` and `measurement-protocol.frozen.md`; `sources.frozen.json` continues to identify exactly that measurement code. `summary.pre-km.json` preserves the original aggregate. Run `node scripts/benchmark-v09-censored-analysis.ts fixtures/benchmarks/raw-v09-v3` to reproduce the corrected aggregate without provider calls. The derived result binds the raw row hash, original measurement source hash, analysis code hash, and prior summary hash. It also validates manifest expectations, censor/finding/exit consistency, formal observation ordinals, and phase accounting. This aggregate correction is explicitly post-hoc, so this recorded run cannot promote feedback. Future fresh runs use the corrected estimator directly and include its helper in the source freeze. A new source revision requires a new output directory; historical raw observations are never rebound to a different measurement source.

The separately versioned `scripts/benchmark-v09-power.ts` supplement writes `fixtures/benchmarks/power-v09.json`. It records 2,200 trials across 22 predeclared effect, baseline-noise, correlated-stream, cache/freshness, transport-uncertainty, model-switch, drift, and virtual rate-limit scheduling conditions, each with 100 fixed seeds. Each formal test uses the production broker and `confirmCandidate`, with a directed billing→general signature chosen before sampling and up to 192 formal plus two discovery calls (model changes can stop a formal test early). The artifact includes each raw trial, call counts, the condition definitions, and its own source hashes; it does not change the 6,000 frozen search measurements.

In that simulator, zero-baseline-noise detection was 26% at effect .1 and 100% at effects .3 and .6. Baseline noise .1 produced 84% inconclusive outcomes, and noise .3 produced 100%; these are recorded outcomes rather than evidence of health. Cache, freshness, transport, drift/model, and virtual scheduling guards use a strong effect to expose failed guards and returned inconclusive for all 100 trials of each tested condition. Correlated streams are reported separately without an independent-sample FWER claim. The virtual rate-limit condition models schedule bias; it does not exercise an HTTP rate-limit service or demonstrate live-provider behavior.
